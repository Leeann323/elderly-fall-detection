# 算法详解：三通道判决与状态机

本文说明 `elderly_fall_monitor.py` 的判决逻辑、为什么这样设计、以及怎么在你的房间里调参。

---

## 1. 为什么不用"摔倒检测"的经典做法

经典做法是训练一个二分类网络（摔倒 / 不摔倒）。在家用场景里它有四个硬伤：

1. **数据不可得**：真实老人跌倒样本极少且涉及隐私，公开数据集多是年轻人"表演摔倒"，分布差异大。
2. **判据单一**：只认"快速倒地"这一种形态。而实际急救统计里，大量事件是**缓慢滑落**（扶墙、扶家具慢慢坐下然后失去意识）和**坐着突然晕厥**——它们的画面里没有"摔"这个动作。
3. **无法解释**：误报时你无法知道模型在怕什么，也就无法调参。
4. **算力**：端侧推理整帧 RGB 分类器成本高。

本项目改成**可解释的几何判据 + 时序状态机**：所有输入都是归一化后的骨架几何量，每个告警都能打印出触发它的具体特征。

---

## 2. 尺度归一化：L_ref

老人身高 1.5 m 和 1.8 m，摄像头 2 m 和 5 m，画面里"多少像素算倒地"完全不同。因此所有长度/速度都以 **L_ref = 肩中点—髋中点距离的中位数** 为单位：

```
开机后最多 15 s（或 120 帧）内采样 torso_px 数组 → median → L_ref
```

- 站立时肩中—髋中距离近似正比于身高（约 0.28 H），因此 `Hh`（头离地比）在人群中稳定在 3 左右。
- 所有阈值都是"多少个躯干长度"，换房间、换镜头无需重调。
- 若标定期间无人出现，会在超时后用 `0.18 * 画面高` 兜底，并在控制台提示。

**注意**：L_ref 在摔倒后不会被重算（只标定一次），所以长时间运行建议固定机位、不要中途移动摄像头。

## 3. 特征定义

| 符号 | 计算 | 直觉 |
| --- | --- | --- |
| `θ` | `atan2(|Δx|, |Δy|)`，颈中→髋中 | 站立 ≈ 0°，横躺 ≈ 90° |
| `R` | 全部关键点外接框 `宽/高` | 竖着的人 < 0.7；横躺 > 1.2 |
| `Hh` | `(脚底 y − 鼻 y) / L_ref` | 站立 3+；坐 2 左右；躺 < 1.3 |
| `hip_h` | `(脚底 y − 髋 y) / L_ref` | 蹲/坐/躺的细分 |
| `knee` | ∠(髋, 膝, 踝)，双膝平均，无有效点时取 180° | 蹲跪时显著变小 |
| `neck` | 头颈向量与"颈→髋反向向量"的夹角 | 低头/垂头时增大 |
| `still` | 相邻帧 33 点平均像素位移 / L_ref / dt | 单位 L/s，越小越"静止" |
| `drop` | `−d(Hh)/dt` | 下坠速度 |
| `omega` | `|dθ/dt|` | 躯干翻转角速度 |

姿态评分（复合门限，防止单一特征误判）：

```
score = 0.50 · clamp((θ − 30)/45) + 0.35 · clamp((R − 0.6)/0.6) + 0.15 · clamp(1 − still/1.5)
```

θ 权重最大（躺倒最可靠），R 次之（横躺时外接框变宽），静止度作为加分项。

## 4. 三通道判决

### A 通道｜冲击型跌倒

```
if drop > IMPACT_DROP(2.5 L/s) or omega > IMPACT_OMEGA(90 deg/s):
    记录 impact_t = now          # 冲击事件存入 1.5 s 有效期
...
if grounded(Hh < 1.3) and now - impact_t <= IMPACT_WINDOW(1.5 s):
    → 候选 A，事件起点 = impact_t（注意：是冲击发生的时刻，不是倒地时刻）
```

**设计要点**：把"冲击"和"贴地"解耦成两个事件，再用时间窗关联。这样既避免"跳一下"被当作冲击（因为 1.5 s 内没有贴地就作废），也避免"蹲下不起来"被当作跌倒（没有冲击、θ 也不够）。

事件起点取 `impact_t` 让告警里的"持续时间"反映真实倒地时长，而不是从判定成立开始计时。

### B 通道｜缓慢滑落型晕倒

```
if hh_prev >= HH_GROUND > hh:    # 头离地比 从"高于门限"跌到"低于门限"
    记录 cross_t = now           # 2.0 s 有效期
if grounded and now - cross_t <= CROSS_WINDOW:
    → 候选 B
```

这是 A 通道的补集：**没有速度峰值**（扶着柜子慢慢滑下），但"头最终低于贴地线"这个几何事实仍然发生。判据极简，误报主要来自"坐地上"或"躺地上休息"，交给下面的状态机与 `score` 门限过滤。

### C 通道｜坐位垂头型晕厥（本项目最有价值的通道）

场景：老人坐在沙发/椅子上，突然脑供血不足失去意识，头慢慢垂下、身体不动，30–60 s 后可能滑落。此时：

- `θ` 很小（身体还是坐姿）、`R` 也不大 → **A/B 通道全部失效**；
- 唯一变化的是 `neck`（垂头角）与 `still`（完全静止）。

```
c_ok = ENABLE_C and seated and neck >= SEAT_ANGLE(55°) and still <= STILL_LIMIT(1.0 L/s)
```

其中 `seated` 的定义：

```
1.3 ≤ Hh < 2.6  且  θ < 45°  且  hip_h < 1.25  且  knee > 75°
```

即"高度在坐位区间、身体基本竖直、髋部不高、膝盖有弯曲"。

- `ENABLE_C` 只对 `SEAT_AREAS = ("客厅","卧室","书房")` 生效，**卫生间默认关闭**（蹲厕是正常行为）。
- C 通道**不参与姿态评分**（`score`），因为坐姿垂头时 θ 和 R 都不显著，用评分会直接把真事件卡掉。
- C 通道用更长的确认窗 `SEAT_CONFIRM = 60 s`，避免"低头看手机"被误报。

### 久蹲旁路提醒（S）

低位姿势（`hip_h < 1.25` 且 `Hh < 2.6`）持续超过 `SQUAT_REMIND_SEC = 900 s` 且状态机仍为 NORMAL → 发一条**软提醒**："已保持低位姿势约 15 分钟，请确认老人状态；如需起身请缓慢，防止体位性低血压。"

它不上报事件编号、不参与去抖与冷却，纯粹是"可能起不来了"的人性化兜底。

## 5. 状态机：为什么必须有观察窗

单帧判定必然误报：**坐下、系鞋带、捡东西、趴地上和宠物玩**都会瞬间满足"θ 大 / Hh 低"。

```
NORMAL ──(通道成立 and score≥0.70 and 连续 3 帧)──> SUSPECT
SUSPECT ──(姿势保持满观察窗)──> ALERT   （A/B: 8 s；C: 60 s）
SUSPECT ──(姿势恢复超过 3 s)──> NORMAL  （撤销）
ALERT  ──(老人自行起身)──> NORMAL       （事件闭环，允许立即上报新事件）
ALERT  ──(300 s 超时)──> NORMAL          （保留冷却窗口，防止刷屏）
```

几个细节值得注意：

- **去抖 `DEBOUNCE_FRAMES = 3`**：连续 3 帧才进入 SUSPECT，过滤掉单帧关键点抖动。
- **撤销比确认快**：确认要 8 s，撤销只要 3 s。理由是不安全方向不对称——真跌倒多躺 3 s 没坏处，误报早 3 s 撤销能显著提升可用性。
- **冷却 `ALERT_COOLDOWN = 60 s`**：同一事件在 60 s 内不重复推送（推送线程与网络抖动叠加时的保护）。
- **目标丢失复位 `LOST_RESET_SEC = 30 s`**：老人走出画面超过 30 s 才复位状态机，短暂遮挡（走过家具后面）不会打断判决。
- **`ALERT_TIMEOUT = 300 s`**：老人一直躺着无法起身时，避免状态机永久卡在 ALERT 而不再上报后续事件。

## 6. 告警内容与落地

事件编号格式 `F%Y%m%d-%H%M-%03d`，例如 `F20261031-1316-001`，同时作为骨架图文件名 → 事件与图片天然可关联。

推送体（钉钉 / 企业微信机器人通用的 markdown 结构）：

```json
{"msgtype": "markdown",
 "markdown": {"title": "跌倒告警",
              "text": "### 【跌倒（冲击型）】客厅\n- 事件编号：F20261031-1316-001\n- 区域：客厅\n- 时间：2026-10-31 13:16:42\n- 持续：8.0 s\n- 置信度：0.83\n- 骨架图：..."}}
```

推送在 `Pusher` 的 daemon 线程里执行，队列长度 32，满了就丢弃并打日志 —— **宁可丢一条告警，也绝不阻塞视频循环**。失败重试 1 次，超时 5 s。

图片在三端各有取舍：

- `PUBLIC_IMAGE_BASE` 为空：消息里写"已保存至本机 alerts/xxx.jpg"（最省事、最保护隐私）。
- 填 `http://<局域网IP>:8000/alerts`：消息内嵌 `![](url)`，需自己起一个静态文件服务（`python -m http.server 8000`）。

## 7. 失效场景清单（部署前务必自查）

| 场景 | 后果 | 缓解 |
| --- | --- | --- |
| 逆光 / 夜间无红外 | 关键点丢失，`lost_since` 触发复位 | 加红外补光，降低 `MIN_VIS` |
| 被子盖住下半身 | 脚踝不可见 → `Hh` 失真 | 代码有兜底：脚不可见时改用 `θ>65° and 鼻低于髋 and 膝>140°` 判定 grounded |
| 多人同框 | 只跟随一个人，可能跟错人 | 限定机位视角，或换多人模型 |
| 摄像头俯视 ≥ 60° | 竖直方向被压缩，`Hh` 判别力下降 | 尽量水平安装，高度 2–2.5 m |
| 坐在低矮沙发 | `hip_h` 偏高，C 通道可能不触发 | 实测后调 `HIP_SEATED_MAX` / `SEATED_HH_MAX` |
| 长时间运行漂移 | `L_ref` 固定，机位变动后失效 | 固定机位；搬动后重启脚本 |

## 8. 调参流程建议（半天可完成）

1. **先只观察、不告警**：`DINGTALK_WEBHOOK=""`，看控制台输出的 `S / hh / hip / neck / v` 在你家客厅的实际分布。
2. **记录三种状态的真实值**：站立、坐下、躺在沙发上，各 30 s，记下 `hh` 与 `hip_h` 区间。
3. **定 `HH_GROUND`**：取"站起来的最低 `hh`"和"躺下时的最高 `hh`"的中点。
4. **定 `SEAT_ANGLE`**：让老人正常看电视 10 分钟，取 `neck` 的 95 分位再加 5°。
5. **压误报**：先用严格阈值（`SCORE_TH=0.80`、`CONFIRM_SEC=12`）跑一周，只把"确实发生过的危险姿势"录下来回放，逐个看是哪一通道触发、哪个特征越界，再放宽。
6. **定期回归**：每次改阈值，用同一段录像回归测试，确保不漏掉已知事件。
